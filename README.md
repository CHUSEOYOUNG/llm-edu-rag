# llm-edu-rag

교육 문서 검색 실험과 근거 인용 RAG 개발 프로젝트.

현재 기본 검색기는 **원문 질문 → BGE-m3 Dense → 본문(body) 색인 top-5**다. 문서명·구조 경로는 검색 벡터에 붙이지 않고 답변 컨텍스트와 출처 표시에 사용한다. 수동 검색문 축약은 별도 실험이며 기본값으로 적용하지 않았다. 로컬 검색 화면에서 1~3개의 짧은 키워드를 입력한 경우에만 Dense 후보 100개 안에서 항목 이름·학교급·본문의 문자 일치를 우선한다. 긴 질문과 CLI·평가 기준선의 Dense 순서는 바꾸지 않는다.

**현재는 유료 API를 사용하지 않는 방향으로 진행한다.** 기본 실행은 로컬 검색과 근거 본문 미리보기이며, 키·모델이 설정되어 있어도 API를 호출하지 않는다. 답변 생성은 아직 사용하지 않는다.

## 최소 RAG 실행

저장소 루트에서 실행한다. 기존 `data/processed/chunks.jsonl`, `embeddings.npy`와 로컬 `BAAI/bge-m3` 캐시가 필요하다. 현재 색인의 해시가 `config/dense_index.json`과 다르면 실행을 중단한다. 원문 자료·임베딩은 저장소에 포함되지 않는다.

### 0. 학교생활 안내 화면 — API 비용 없음

```sh
uv run python src/search_app.py
```

브라우저에서 <http://127.0.0.1:8765/>를 연다. 이미 서버가 실행 중이면 다시 실행할 필요 없다. 포트가 다른 프로그램에서 사용 중이면 `--port 8766`을 붙이고 표시되는 주소로 접속한다. 직접 실행한 터미널에서 `Ctrl+C`로 종료한다.

- 질문 또는 추천 질문으로 검색하고, 관련 자료를 선택해 내용을 확인한다.
- 선생님·학생·학부모 선택은 추천 질문만 변경한다. 검색 범위를 몰래 바꾸거나 질문에 조건을 추가하지 않는다.
- 검색 개수는 5·10·20개 중 선택한다. 기본 5개는 기존 Dense 기준선과 동일하다.
- `출결`, `중학교 출결`처럼 짧게 검색하면 정확히 일치하는 항목 이름과 학교급을 먼저 보여준다. 문장형 질문은 기존 의미 검색 순서를 유지한다.
- 학교급·시행일 등의 표현이 내용·항목 이름·자료 이름 중 어디에 있는지 쉬운 말로 표시한다. 적용 여부를 자동 판정하는 기능은 아니다.
- 내용 복사와 읽기 쉬운 텍스트 파일 저장을 제공한다. 저장 파일에는 질문·자료 이름·본문이 포함되므로 공유 전 확인한다. 개발자용 JSON은 CLI와 HTTP 응답에만 남긴다.
- 검색 결과에 원본 PDF의 실제 페이지 범위를 표시한다. `원문에서 확인하기`를 누르면 허용된 로컬 PDF를 해당 페이지로 연다.
- 화면에서는 청크 ID, 검색 점수, 모델명, 처리 시간을 표시하지 않는다. 원자료의 문장은 그대로 보존한다.
- 원본 데이터는 그대로 보존한다. 화면·복사·저장에서는 PDF 추출 과정의 `<br>`·주석 같은 표시 코드를 제거하고, 마크다운 표를 읽기 쉬운 표로 바꾼다. 모든 셀은 텍스트로만 넣어 문서 속 HTML을 실행하지 않는다. 페이지는 PDF 파싱 시 기록한 실제 경계만 사용한다.

웹 서버에는 생성 API 경로가 없다. 추가 라이브러리 설치·외부 폰트·CDN·모델 다운로드 없이 기존 로컬 색인을 사용한다. `127.0.0.1`에만 바인딩하며 원문 질문을 서버 로그에 기록하지 않는다. 공개 배포용 서버가 아니므로 포트 포워딩이나 외부 공개에 사용하지 않는다.

단위 테스트, 실제 HTTP 검색, 브라우저에서 검색 결과와 원문 PDF 페이지 열기를 확인했다. 자세한 검증 상태는 `notes/2026-08-27-search-ui.md`에 기록했다.

### 1. 키 없이 실제 검색 확인

```sh
uv run python src/rag.py "생기부 글자수 셀 때 한글 한 글자는 몇 바이트로 계산되나요?" --output runs/retrieval.json
```

이 모드는 실제 검색만 수행하며 API 사용료가 발생하지 않는다. 터미널에는 출처별 본문을 최대 700자까지 보여주고 전체 본문은 JSON에 보존한다. `retrieved_only`는 답변 생성 또는 답변 가능 판정 성공을 뜻하지 않는다. JSON에는 원문 질문, 조건 일부, 검색 점수, 본문, 문서명, 구조 경로, PDF 페이지 범위가 저장된다. `runs/`는 Git에서 제외한다. 기존 `--dry-run` 옵션도 호환용으로 유지한다.

### 2. 선택 사항: 생성 API 설정 — 현재 진행하지 않음

아래 설정은 향후 유료 API를 사용하기로 결정했을 때만 필요하다. 로컬 검색에는 키·결제 설정이 필요 없다. 생성하려면 반드시 `--generate`를 명시해야 한다.

`.env.example`을 `.env`로 복사한 뒤 로컬 편집기에서 값을 입력한다. 기존 `.env`가 있으면 덮어쓰지 않는다.

```dotenv
OPENAI_API_KEY=본인의_API_키
OPENAI_MODEL=본인_계정에서_사용할_모델_ID
```

키는 채팅·소스 코드에 붙이지 않는다. `.env`는 Git에서 제외하며 프로그램이 자동으로 읽지는 않는다. 아래의 `uv run --env-file .env`로 불러온다. Responses API의 structured outputs를 지원하고 계정에서 사용할 수 있는 모델을 명시해야 한다. 임의의 기본 모델은 지정하지 않았다.

```sh
uv run --env-file .env python src/rag.py "생기부 글자수 셀 때 한글 한 글자는 몇 바이트로 계산되나요?" --generate --output runs/answer.json
```

생성 모드는 질문·검색된 본문·문서명·구조 경로를 OpenAI API로 전송하며 API 비용이 발생할 수 있다. API 키는 요청 인증에만 사용한다. `store=false`, 요청 시간 제한 45초, 출력 토큰 상한 4,000으로 설정했다. 자동 재시도·도구 호출은 없다. HTTP 오류 본문이나 인증 헤더는 출력하지 않는다.

연결부는 추가 SDK 없이 Python 표준 라이브러리로 구현했다. 요청 형식과 거절 처리는 [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했다. **실제 API 생성 응답은 아직 검증하지 않았다.**

### 3. 평가셋 점검

```sh
# 13개 질문 모두 실제 검색. API 호출 없음.
uv run python src/check_rag.py

# API 설정 후 한 질문의 생성부터 확인. 이 명령은 API를 호출한다.
uv run --env-file .env python src/check_rag.py --generate --qid q003 --output runs/rag-q003.json

# 단위 테스트
uv run python -m unittest discover -s tests -v
```

생성 점검에 `--qid`를 주지 않으면 13개 모두 처리하므로 먼저 단일 질문으로 확인한다. q008 등 사전 날짜 점검에서 보류된 질문은 API를 호출하지 않는다. `check_rag.py`는 골드를 검색 후 진단에만 사용하며, 생성기에 전달하지 않는다. 답변 품질 자동 채점은 아직 없다.

## 답변과 출처 처리

1. 원문 질문 전체로 검색한다. 학교급·시행일을 포함한 원문은 생성 단계까지 그대로 전달한다.
2. 청크 전체를 컨텍스트에 넣고 `[S1]` 같은 ID를 붙인다. 기본 문자 예산은 24,000자이며 넘치는 청크는 통째로 제외하고 누락 ID를 기록한다. 문자 예산은 토큰 상한과 같지 않다.
3. 모델은 사실 문장별 근거 인용과 적용 조건 점검을 JSON으로 반환한다.
4. 프로그램은 출처 ID가 컨텍스트에 있는지, 인용문이 해당 필드의 연속된 원문과 일치하는지 검사한다. 사실 문장에는 본문 인용이 하나 이상 필요하다. 검증 후에만 인용 표기를 붙인다.

PDF 파싱 단계에서 각 페이지의 실제 문자 경계를 기록하고 섹션과 검색 단위까지 전달한다. 여러 페이지에 걸친 표나 본문은 시작~끝 페이지 범위로 표시한다. 문서명·구조 경로·청크 ID도 함께 보존한다.

| 상태 | 의미 |
|---|---|
| `retrieved_only` | 검색만 실행, 답변 생성·답변 가능성은 미평가 |
| `draft_answer` | 출처 ID·인용문 검증을 통과한 답변 초안 |
| `insufficient_evidence` | 현재 컨텍스트로 답변을 보류함. 코퍼스 전체에 답이 없다는 판정은 아님 |
| `validation_failed` | 인용 오류·조건 누락 등으로 생성 답변을 숨김 |
| `generation_error` | API·네트워크·응답 형식 오류. 검색 실패와 구분 |

## 아직 해결하지 않은 부분

- **원문 일치는 사실성 검증이 아니다.** 인용이 주장·예외·표 헤더를 실제로 뒷받침하는지, 학교급이나 시점이 맞는지는 별도 검토가 필요하다.
- 조건 추출은 날짜·학교급 등 일부 정규식이다. 전체 의미 분석이나 메타데이터 필터가 아니다. 원문 질문이 항상 기준이다.
- `YYYY년 M월 D일` 형태의 질문 날짜가 본문·구조 경로에 문자 수준으로 없으면 생성을 보류한다. 날짜 표기가 달라 생기는 과도한 보류가 있을 수 있고, 날짜가 있어도 적용 관계가 입증된 것은 아니다. 파일명만의 날짜는 이 검사에 사용하지 않는다.
- q006은 기존 top-5에서 두 학교급 근거를 모두 회수하지 못한다. 생성만 붙인다고 검색 누락이 해결되지는 않는다.
- q012·q013은 검색 실행만 확인했다. 모델이 답변을 적절히 보류하는지 아직 실측하지 않았다.
- 프롬프트에 자료 속 지시를 따르지 말라고 명시했지만 프롬프트 주입 방어가 완성된 것은 아니다.
- 실제 생성 품질 평가, 자동 의미 검증, FastAPI 서빙은 후속 단계다.
