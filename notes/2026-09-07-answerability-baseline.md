# 답변 가능 여부 점수 기준 실험

## 목적

검색기가 코퍼스에 없는 질문에도 항상 가까운 문서를 반환하는 문제를 확인했다. Dense 최고 유사도만으로 답변 가능 여부를 판별할 수 있는지 먼저 재고, 서비스에서 안전하게 쓸 수 있는 범위를 정했다.

## 입력

- 모델: `BAAI/bge-m3`
- 색인: body-only Dense
- 평가 질문: `eval/questions.v2.draft.jsonl`
- 답변 가능 11개, 답변 불가능 2개
- 같은 개발셋에서 기준을 탐색했으며 별도 테스트셋은 사용하지 않음

실행 명령은 다음과 같다.

```sh
uv run python src/evaluate_answerability.py
```

결과 원본은 `experiments/answerability_baseline.json`에 저장한다.

## 결과

| 항목 | 값 |
|---|---:|
| ROC-AUC | 0.818 |
| 검토 안내 기준 | 0.610 |
| Recall | 0.818 (9/11) |
| Specificity | 1.000 (2/2) |
| Balanced accuracy | 0.909 |
| Accuracy | 0.846 (11/13) |

점수 분포에는 겹침이 있었다. 답을 찾을 수 있는 q002의 최고 점수는 `0.566`이지만, 답을 찾을 수 없는 q012와 q013은 각각 `0.608`, `0.599`였다. 검색 점수는 주제가 가까운지를 나타낼 뿐, 해당 문장이 질문의 답을 실제로 포함하는지는 보장하지 않았다.

## 서비스 반영

`0.61` 이상은 `strong_candidate`, 그 아래는 `review_recommended`로 표시한다. 학교급 필터 뒤에 자료가 하나도 없으면 `no_results`로 표시한다.

`review_recommended` 결과도 화면에서 없애지 않는다. 대신 학교급, 학년, 연도를 더해 다시 검색하거나 원문을 직접 확인하라는 안내를 보여준다. API의 `answerability_verified`는 항상 `false`다. 이 값은 자동 답변 가능 판정이 아니라 검토 우선순위를 위한 개발 기준이다.

## 한계와 다음 실험

- 답변 불가능 질문이 두 개뿐이라 수치 변동이 크다.
- 기준 선택과 평가에 같은 개발셋을 사용했다.
- 코퍼스와 모델이 바뀌면 점수 기준도 다시 측정해야 한다.
- 최소한 답변 가능/불가능 질문을 각각 30개 이상으로 늘리고, 기준을 고르는 데이터와 최종 확인 데이터를 분리해야 한다.
- 이후에는 CrossEncoder 점수, 질문의 요구 조건과 본문 문장 간 entailment, 생성 모델의 보류 응답을 별도로 비교한다.
