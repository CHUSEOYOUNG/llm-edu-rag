# V2 개발 평가셋 기준선

## 범위

50문항 후보 중 개발 분할 35문항만 사용했다. 답변 가능 질문은 27개, 코퍼스에 답이 없어야 하는 질문은 8개다. 새 문항은 로컬 코퍼스와 다시 대조한 assistant-reviewed 초안이며 교육 정책 전문가의 검수 결과는 아니다. 최종 테스트 15문항은 실행하지 않았다.

## 검색 평가 전에 고친 주석 문제

첫 실행의 Complete@5는 0.7407이었다. 실패 결과를 읽어 보니 검색 1위가 정답 문장을 포함해도 고등학교판 청크 하나만 골드로 등록해 초등학교판이나 중학교판의 같은 규정을 오답 처리한 경우가 있었다. 주소 변경, 출결 정의, 학생선수 출결, 생기부 정정 절차의 동등 근거를 확인해 대체 근거로 추가했다.

이 수정은 검색 알고리즘 개선으로 계산하지 않는다. 평가 주석 오류를 바로잡은 작업이다.

| 검색 지표 | 검수 후 개발 기준선 |
| --- | ---: |
| Recall@5 | 1.0000 |
| Complete@5 | 1.0000 |
| MRR@10 | 0.8377 |

표 질문 6개와 후속 질문 5개도 모두 Complete@5를 통과했다. 후속 질문 중 `그럼 5~6학년은?`은 이전 질문의 학년군만 교체하도록 재작성 규칙을 보완했다.

## 생성 기준선

수정 전 전체 개발셋을 Qwen3 4B로 한 번 실행했다.

| 생성 지표 | 결과 |
| --- | ---: |
| 전체 작업 성공률 | 0.8571 |
| 답변 가능 질문 성공률 | 0.8148 |
| 답 없음 거절률 | 1.0000 |
| 인용 형식 통과율 | 0.8148 |
| 생성 지연 p50 | 13.75초 |
| 생성 지연 p95 | 39.75초 |

실패는 다중 근거 질문 1개와 표 질문 4개였다. 표 질문은 검색에 성공했지만 생성용 문맥을 줄이는 과정에서 표 대신 `정보교육 34/68시간` 문단을 선택해 학년과 기간 조건이 사라졌다. 표·시수 질문은 표 전체와 기간 주석을 유지하도록 바꿨다.

학생선수 질문에서는 모델이 프롬프트에 없는 근거 번호를 반환했다. Ollama에 전달하는 JSON Schema의 근거 번호 항목을 실제 제공한 ID의 enum으로 제한했다.

## 표 오답을 잡은 과정

저장된 전체 생성 결과를 숫자 기준으로 다시 검사하니 숫자가 포함된 질문 19개 중 13개만 기준 답의 숫자를 모두 포함했다. 숫자 일치율은 `0.6842`였다. 실패 상태였던 5개 외에도 후속 질문 `그럼 5~6학년은?`이 `408시간` 대신 `2,176시간`을 답하고 인용 검사를 통과했다. 인용 형식 검사는 답의 의미가 맞는지 확인하지 않는다는 실제 사례다. 재검사 결과는 `experiments/gold_v2_development_generation_numeric_audit.json`에 보존했다.

원인은 표 파서가 `수학의`, `영어의`에서 조사를 제거하지 못해 과목 행이 아니라 `학년군별 총 수업 시간` 행을 선택한 것이었다. 조사 정규화 후 구조화 값은 다음처럼 바뀌었다.

```text
수학 · 3~4학년 · 272시간 · 2년간
영어 · 5~6학년 · 204시간 · 2년간
국어 · 5~6학년 · 408시간 · 2년간
```

해당 표 문항과 후속 질문을 다시 실행해 답변 상태, 인용, 기준 답 숫자 일치가 모두 통과하는 것을 확인했다. 평가 결과에도 `reference_number_match_rate`를 추가했다. 이 검사는 숫자 오답을 찾는 보조 지표이며 문장 전체의 의미 정확성을 보장하지 않는다.

## 해석과 다음 확인

- 검색은 assistant-reviewed 개발 질문에서 필요한 근거를 모두 상위 5개 안에 넣었다.
- 생성의 초기 병목은 검색보다 표 문맥 선택과 근거 번호 출력이었다.
- 35문항 전체 생성에는 약 8분이 걸려 매 변경마다 실행하기에는 무겁다.
- 수정 후에는 실패 문항만 재실행했다. 전체 35문항의 수정 후 생성 점수는 아직 다시 측정하지 않았으므로 100%라고 보고하지 않는다.
- 숫자가 없는 답변의 의미 정확도와 정책 최신성은 여전히 사람 검수 대상이다.
