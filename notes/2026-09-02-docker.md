# Docker 실행 구성

FastAPI 검색 서비스를 같은 환경에서 다시 실행할 수 있도록 Dockerfile과 Compose 구성을 추가했다. 원문 PDF와 임베딩은 저장소에 없고 BGE-m3 로컬 캐시는 4GB가 넘기 때문에 이미지 안에 복사하지 않는다. 세 입력은 실행 시 읽기 전용으로 연결한다.

## 구성

- Python 3.12 slim 기반 이미지
- `uv.lock`에 고정된 운영 의존성만 설치
- 소스보다 의존성을 먼저 설치해 Docker 레이어 캐시 활용
- UID 10001 비루트 사용자로 Uvicorn 실행
- `data/raw`, `data/processed`, Hugging Face 캐시를 읽기 전용 마운트
- 컨테이너 루트 파일시스템 읽기 전용
- Linux capability 전체 제거와 `no-new-privileges` 적용
- 호스트에서는 `127.0.0.1:8765`로만 접근
- `/health`를 이용한 컨테이너 상태 확인
- `.git`, `.env`, 데이터, 모델, 실험 결과를 빌드 컨텍스트에서 제외

의존성 레이어를 분리하고 `uv sync --locked --no-install-project`를 사용하는 방식은 [uv의 Docker 가이드](https://docs.astral.sh/uv/guides/integration/docker/)를 참고했다.

## 실행

먼저 로컬에서 데이터 색인과 BGE-m3 캐시를 준비한 다음 실행한다.

```sh
docker compose up --build
curl http://127.0.0.1:8765/health
docker compose down
```

## 확인 범위

- 컨테이너 파일의 고정 의존성, 비루트 사용자, 오프라인 모델 설정을 자동 테스트
- Compose의 loopback 포트, 읽기 전용 입력, capability 제거를 자동 테스트
- `.dockerignore`가 데이터와 비밀 파일을 제외하는지 자동 테스트
- 전체 Python 테스트 78개와 JavaScript 테스트 8개 통과

현재 작업 환경에는 `docker` 명령이 설치되어 있지 않아 이미지 빌드와 컨테이너 기동은 실행하지 못했다. 따라서 실제 이미지 크기, Linux에서 BGE-m3 로딩, healthcheck 완료 시간은 검증한 것으로 기록하지 않는다. Docker Desktop 또는 Docker Engine이 있는 환경에서 위 실행 명령으로 확인해야 이 단계를 최종 완료로 처리한다.
