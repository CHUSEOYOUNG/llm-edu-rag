# 최소 RAG 구현 및 오프라인 검증

## 현재 상태

비용 제약에 따라 유료 API 연결을 중단했다. 기본 CLI는 키 유무와 무관하게 로컬 검색·본문 미리보기만 실행한다. 생성 API는 명시적인 `--generate`가 있어야 호출할 수 있다. 기존 `--dry-run`은 호환용으로 유지한다.

기존 원문 Dense 검색에 컨텍스트 구성, 생성 API 연결부, 인용 검증, 답변 보류를 연결했다. **실제 LLM 생성 호출과 답변 품질 평가는 아직 하지 않았다.** 실행 환경에 `OPENAI_API_KEY`와 `OPENAI_MODEL` 설정이 없었다. 아래의 성공은 검색·프로그램 검증 결과이지 생성 답변의 정확도 결과가 아니다.

## 구현 범위

- `src/rag.py`: 원문 질문의 body-only Dense 검색, 출처 ID·문서명·구조 경로·본문 패킷, 인용 검사, CLI.
- `src/rag_generate.py`: OpenAI Responses REST 요청, JSON Schema 출력, 완료·거절·API 오류 처리. 추가 의존성 없음.
- `src/check_rag.py`: 고정된 개발 질문 13개를 검색하거나, 명시적인 `--generate`로 생성 점검. 기본값은 API 호출 없음.
- `config/dense_index.json`: 현재 코퍼스와 임베딩의 지문. 기존 색인 또는 행 순서가 바뀌면 중단한다.
- `tests/test_rag.py`: 신규 테스트 21개. 기존 21개와 합쳐 42개. 기본 실행은 키가 있어도 생성기를 호출하지 않는지 검사한다.
- `.env.example`, `.gitignore`, `README.md`: API 설정 예시, 비밀·개인 실행 로그 제외, 실행 안내.

검색 알고리즘, 임베딩, 코퍼스, 평가 질문·정답, 고정 스냅샷은 바꾸지 않았다. 수동 핵심 검색문도 기본값으로 사용하지 않는다.

## 검증이 보장하는 것과 보장하지 않는 것

사실 문장마다 실제 컨텍스트의 본문 인용이 필요하다. 프로그램은 인용의 출처 ID, 필드, 연속된 원문 일치를 확인하고 원문 오프셋을 기록한다. 검증 실패 시 생성 답변을 숨긴다. 모델이 인용 표기를 직접 삽입하지 않고 검증된 ID를 프로그램이 붙인다.

반면 인용 내용이 주장과 의미상 연결되는지, 숫자가 올바른 표 헤더·기간에 해당하는지, 적용 범위가 정확한지는 독립적으로 검증하지 않는다. 따라서 통과 상태도 `draft_answer`이며 `semantic_entailment=not_verified`를 표시한다.

조건 목록은 원문에서 날짜·고시·교육과정·학교급·학년·기간 일부를 추출한 것이다. 완전한 조건 해석기나 검색 필터가 아니다. 생성 단계는 전체 원문 질문을 기준으로 삼도록 지시한다.

`YYYY년 M월 D일` 조건은 컨텍스트의 본문 또는 구조 경로에 문자 수준으로 있어야 생성을 시도한다. 파일명만의 날짜는 인정하지 않는다. 이 규칙은 날짜 표기가 다르면 과도하게 보류할 수 있고, 날짜가 존재해도 적용 대상과의 관계를 입증하지는 않는다. 날짜가 확인되지 않으면 `insufficient_evidence`로 보류한다. 코퍼스 전체에 답이 없다는 뜻은 아니다.

참고 문서 속 지시를 따르지 않도록 시스템 지시와 자료 JSON을 분리했지만, 프롬프트 주입 방어의 완성을 주장하지 않는다.

## 실행

저장소 루트에서:

```sh
# 실제 검색만 실행. API 키 불필요.
uv run python src/rag.py "생기부 글자수 셀 때 한글 한 글자는 몇 바이트로 계산되나요?" --dry-run --output runs/retrieval-q003.json

# 개발 질문 13개 실제 검색. 결과에는 생성 답변이 없다.
uv run python src/check_rag.py

# 테스트
uv run python -m unittest discover -s tests -v
```

원시 검색 결과는 `runs/rag_smoke.json`에 저장된다. 개인 질문과 문서 본문이 들어갈 수 있으므로 `runs/`는 Git에서 제외한다. API 키와 모델은 `.env.example`을 참고해 로컬 `.env`에 설정한다. 키를 채팅이나 Git에 올리지 않는다.

향후 유료 API 사용을 다시 결정한 경우에만 설정 후 q003 하나로 생성 점검한다. 현재는 실행하지 않는다:

```sh
uv run --env-file .env python src/check_rag.py --generate --qid q003 --output runs/rag-q003.json
```

이 명령은 원문 질문·검색된 본문·문서명·구조 경로를 OpenAI API에 보내며 API 비용이 발생할 수 있다. 설정할 모델은 계정에서 사용 가능하며 Responses structured outputs를 지원해야 한다. 임의의 기본 모델을 정하지 않았다. 연결부는 [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했다.

그 후 q004·q006·q008 및 답변 불가 질문 q012·q013에서 인용, 조건 누락, 보류 여부를 사람이 검토한다. 실제 답변 품질을 확인하기 전에는 FastAPI 배포나 검색기 최종 확정으로 넘어가지 않는다.

이번 변경은 커밋·푸시하지 않았다.
