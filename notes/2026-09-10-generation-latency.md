# 로컬 답변 생성 지연 개선

## 문제

M2 MacBook Air 16GB에서 `qwen3:4b-instruct`가 CPU로 실행된다. 검색은 모델이 준비된 뒤 대체로 2초 이내였지만, 답변 생성은 약 20~50초가 걸렸다. 기존 초등학교 수업 시간 질문은 입력 1,806토큰과 출력 214토큰을 사용했다.

## 변경

- 일반 질문은 검색 1위 원문을 우선 사용하고, 비교 질문만 최대 두 자료를 전달한다.
- `몇 분`, `몇 일` 같은 수치 질문은 숫자와 요청 단위가 함께 있는 완전한 문단만 전달한다.
- 축소한 문단에 학교급·학년·날짜 조건이 실제로 없으면 그 후보를 건너뛴다.
- 모델이 생성하던 적용 범위 JSON은 원문의 문자 일치로 프로그램에서 만든다.
- 최대 출력은 256토큰으로 줄이고 모델 유지 시간을 2분에서 10분으로 늘렸다.
- Ollama가 보내는 적재·입력 처리·출력 시간을 API 응답에 기록한다.

문단 중간을 자르지 않고 생성된 인용이 전달한 원문에 실제로 있는지도 이전과 같이 검사한다.

## 확인 결과

단일 실행값이라 정식 성능 평가가 아닌 개발 중 측정치다.

| 질문 | 전체 시간 | 입력 토큰 | 출력 토큰 | 결과 |
| --- | ---: | ---: | ---: | --- |
| 초등학교 수업은 몇 분인가요? (반복 실행) | 8.3초 | 595 | 125 | 40분, 인용 통과 |
| 중학교 수업 한 시간은 몇 분인가요? (새 질문) | 12.1초 | 588 | 125 | 45분, 인용 통과 |
| 학교폭력 4·5호 조치는 언제 삭제되나요? | 17.1초 | 1,055 | 86 | 졸업 후 2년, 인용 통과 |

초등학교 수업 시간 질문의 생성 입력은 1,806토큰에서 약 600토큰으로 줄었다. 최초 요청은 Ollama 모델 적재에 약 5초가 추가될 수 있다. 측정값은 질문, 운영체제 부하, 프롬프트 캐시 상태에 따라 달라진다.
