# 검색문 표현 비교: 원문 질문 vs 수동 핵심 검색문

## 결론

고정한 v2 개발셋 11개에서 핵심 검색문은 Complete@5를 9/11에서 10/11로 높였다. q006·q008은 회복했지만 q004는 정답 근거가 2위에서 10위로 밀렸다. **기본 검색기는 원문 질문을 사용하는 Dense body-only로 유지하고, 수동 축약은 탐색 실험으로 남긴다.**

q008의 성공은 사전에 주석으로 확인한 교과 목록을 찾았다는 뜻이다. 검색된 문서가 질문의 시행일에 적용되는지 자동으로 검증했다는 뜻은 아니다.

## 실험 조건

- 기준 커밋: `1658001`.
- 고정 평가셋: `eval/snapshots/v2-development-11q-2026-08-27/`의 답변 가능한 질문 11개. q012·q013의 답변 불가 판정은 이번 범위에 없다.
- 모델·코퍼스: `BAAI/bge-m3`, 기존 1,331개 청크의 body-only 임베딩, 동일 점수 계산과 top-20 검색.
- 비교: 원문 질문 전체(`full`)와 질문별 수동 핵심 검색문 하나(`manual_core`). 검색 결과를 본 뒤 검색문을 고르거나 재작성하지 않았다.
- 검색문 작성자는 이전 평가셋과 실패 분석을 이미 보았다. 정답 값이나 `source_hint`를 검색 입력으로 넣지는 않았지만, 블라인드 실험 또는 독립 테스트셋 평가는 아니다.
- 학교급·학년 등은 검색문에도 유지했다. 일부 교육과정 버전·고시·시행일은 검색문에서 빼고 원문 질문 및 별도 조건 목록에 보존했다. **조건을 보존했을 뿐, 검색 필터나 적용 여부 검증기는 구현하지 않았다.**
- 질문·정답 근거·청크·임베딩·기존 검색기 구현은 변경하지 않았다.

## 전체 결과

| 지표 | 원문 질문 | 핵심 검색문 |
|---|---:|---:|
| Hit@1 | 0.455 | 0.727 |
| Coverage@1 | 0.455 | 0.727 |
| Complete@1 | 0.455 | 0.727 |
| Hit@5 | 0.818 | 0.909 |
| Coverage@5 | 0.818 | 0.909 |
| Complete@5 | 0.818 (9/11) | 0.909 (10/11) |
| Hit@10 | 0.909 | 1.000 |
| Coverage@10 | 0.864 | 1.000 |
| Complete@10 | 0.818 | 1.000 |
| MRR@20 | 0.636 | 0.812 |

Hit는 필요한 근거 그룹 중 하나라도 찾은 질문 비율, Coverage는 질문별 근거 그룹 회수율의 평균, Complete는 필요한 모든 그룹을 찾은 질문 비율이다. 각 그룹의 대체 근거들은 OR로 판정한다. MRR@20은 첫 번째 근거의 역순위 평균이며 모든 조건을 충족하는 답변 품질을 측정하지 않는다. 과거 v1의 청크 단위 Recall과 직접 비교하면 안 된다.

### q004: 축약에 의한 회귀

원문은 허용 조정 범위와 제한 교과가 함께 있는 청크를 2위에서 찾았다. 핵심 검색문은 같은 청크를 10위로 밀었다. 상위 5개에는 특수한 학교의 편성 예외, 출결상 수업일수 규정, 일반적인 시간 배당 설명 등이 들어왔다. 확인한 본문은 고정 주석이 요구하는 조정 범위와 제한을 충족하지 않았다.

측정한 지표 중 악화는 q004에서만 발생했다(상위 5개 지표와 MRR). 이 결과를 본 뒤 q004만 다시 쓰거나 원문으로 되돌린 혼합 점수를 이번 실험 성적으로 보고하지 않는다.

### q006: 두 학교급의 근거 회수

초등학교·중학교 근거가 각각 6·16위에서 3·5위로 올라왔다. 두 근거가 top-5에 들어온 것이며, 1위 문서가 곧 적절한 답이라는 뜻은 아니다.

### q008: 교과 목록 회수와 시행일 검증의 차이

교과 목록 근거 `s019::1::0`은 >20에서 1위로 올라왔다. 하지만 핵심 검색문의 top-5에서 `2028년 3월 1일`은 본문과 메타데이터 어느 쪽에도 문자 수준으로 발견되지 않았다. 요청 고시명은 1·4·5위의 메타데이터에 있었지만 본문에는 없었다. 파일명이 같다고 그 안의 모든 조항·과거 개정 내용이 같은 날짜에 적용되는 것은 아니다.

이 평가의 q008 근거 그룹은 요청한 교과 목록을 대상으로 한다. 시행일은 질문에 주어진 범위이며 이전 PDF 검토에서 주석 범위를 확인했다. 이번 점수는 **검색된 컨텍스트만으로 시행일 관계까지 입증했다는 점수로 해석할 수 없다.** 출력의 `semantic_scope_validation`은 `not_implemented`, 문자 점검의 `semantic_verdict`는 `unknown`으로 유지했다.

## 검증 및 재현

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python src/ablation_query_expression.py
```

로컬에 준비된 모델 캐시와 기존 코퍼스·임베딩이 필요하다. 실행은 오프라인 모델 로딩을 사용한다.

- 21개 단위 테스트 통과(기존 15개 + 신규 6개).
- 실제 비교 실행 완료. 원문 질문 11개의 top-20 청크 순서가 고정 기준선과 정확히 일치했다.
- 저장된 전체·질문별 원문 지표도 고정 기준선과 일치했다.
- 스냅샷 체크섬, 실행 전 검색문 계획 해시, 작업용 v2와 고정 v2의 동일성을 확인했다.
- 두 비교군의 원문 질문과 조건 목록이 동일하게 보존되는지 확인했다.
- 실행 코드는 코퍼스·임베딩·v1·v2 입력 해시, 주석, 질문 범위를 검증한다. 검색문 검증에는 질문 텍스트만 넘기며 근거 정답은 검색 후 평가에 사용한다.

## 해석 한계와 다음 단계

11개 개발 질문에서 얻은 수동 탐색 결과다. 축약과 표현 변경이 함께 일어나므로 특정 단어나 길이 감소만의 효과라고 분리할 수 없다. 조건의 검색문 제외도 일부 결과에 영향을 줄 수 있다. 자동 질의 변환기나 새로운 질문에서의 성능은 평가하지 않았다.

기존 Dense 원문 검색을 기본값으로 유지한다. 다음 구현 단계는 이 검색기에 **원문 질문·조건·출처를 함께 전달하는 최소 RAG**를 연결하는 것이다. 답변이 인용 근거를 벗어나거나 적용 범위를 확인할 수 없는 경우를 별도로 표시하고, 검색 점수와 생성 답변 평가는 나누어 기록한다. 특히 q004·q006·q008과 답변 불가 질문 q012·q013을 확인 사례로 삼는다.

원문과 축약문 후보를 함께 검색하는 방식도 후속 실험 후보지만 아직 구현·검증하지 않았다. 원문 후보 보존만으로 최종 top-5나 답변 품질이 개선된다고 단정하지 않는다. 최소 RAG도 이번 변경에는 포함하지 않았다.
