# 전처리 Ablation — 2026-07-28

## 설계

동일 원본 페이지에서 정규화 조합을 바꿔 청킹 → BM25 평가.

| 조건 | 가운뎃점 정규화 | 머리말 제거 |
|------|------|------|
| raw  | ✗ | ✗ |
| dot  | ✓ | ✗ |
| head | ✗ | ✓ |
| both | ✓ | ✓ |

### 평가 방법 전환
chunk_id가 섹션 순번 기반이라 전처리를 바꾸면 식별자가 전부 어긋남.
→ gold 판정을 chunk_id가 아닌 **정답 문자열 포함 여부**로 변경.
   Ablation을 하려면 평가 기준이 파이프라인 산출물에 의존하면 안 됨.

## 결과

| 설정 | 청크 | R@1 | R@5 | R@10 | MRR |
|------|------|------|------|------|------|
| raw  | 1359 | 0.227 | 0.524 | 0.668 | 0.411 |
| dot  | 1354 | 0.227 | 0.524 | 0.668 | 0.412 |
| head | 1334 | 0.227 | 0.524 | 0.668 | 0.434 |
| both | 1331 | 0.227 | 0.524 | 0.668 | 0.435 |

질문별 R@5는 11개 전부 조건 간 동일.

## 해석 (negative result)

**Recall은 전처리에 전혀 반응하지 않음.**

- 가운뎃점 정규화(643개 제거): MRR +0.001. 사실상 0.
  코퍼스 107만 자 대비 0.06%이며, Kiwi 형태소 분석기가
  가운뎃점을 기호로 분류해 토큰에서 이미 제외함.
- 머리말 제거(2,275줄): MRR +0.023.
  질의 11개 기준 순위 1단계 상승 수준으로, 통계적 유의성 없음.

## 그럼에도 전처리가 필요했던 이유

검색 지표로는 안 나타나지만 **섹션 구조 복원에는 필수**였음.

머리말 미제거 시 "Ⅰ. 교육과정 구성의 방향"이 페이지마다 반복되어
섹션 파서가 트리를 계속 리셋 → 고아 빈섹션 34% 발생 (발견 3, 5 참조).
가운뎃점 고아 줄은 merge_orphans가 열거 항목으로 오인.

→ 전처리의 기여는 검색 성능이 아니라 **구조 품질**에 있음.
   Recall/MRR로는 측정되지 않는 종류의 개선.

## 부수 발견

### strip_running_heads 과다 삭제
초기 구현에서 페이지 내용을 100% 삭제하는 버그.
반복 패턴을 전 페이지에서 제거하면서 첫 등장 보존 로직이
스코프 문제로 동작하지 않았음.
→ 삭제 후 잔존율 30% 미만이면 원본 롤백하는 안전장치 추가.

### 모듈 진입점 분리
chunk.py, build_sections.py가 import 시 전체 실행됨.
실험 스크립트에서 함수만 재사용하려면 `if __name__ == "__main__"` 필요.
→ 실험을 여러 조건으로 반복하려면 스크립트/모듈 분리가 선행되어야 함.
