# 50문항 평가셋 작성 작업

이 디렉터리의 `candidates.jsonl`은 공식 골드셋이 아니라 **검수용 초안**이다. 기존 13문항과 새 후보 37문항을 한곳에서 검토하기 위해 만들었다.

## 구성

| 유형 | 개발 | 최종 테스트 | 합계 |
| --- | ---: | ---: | ---: |
| 단일 근거 | 8 | 2 | 10 |
| 여러 근거 | 8 | 2 | 10 |
| 표·기간·수치 | 6 | 4 | 10 |
| 후속 질문 | 5 | 5 | 10 |
| 답 없음 | 8 | 2 | 10 |
| 합계 | 35 | 15 | 50 |

개발 문항은 검색과 생성 문제를 고칠 때 사용한다. 최종 테스트 15문항은 구현 선택이나 임계값 조정에 사용하지 않는다. 같은 사실을 표현만 바꾼 질문이 두 분할에 들어가지 않도록 `fact_key`를 검사한다.

## 상태의 의미

- `assistant_reviewed_draft`: 기존 13문항. 회귀 확인에는 사용할 수 있지만 전문가 검수는 끝나지 않았다.
- `pending_human_review`: 새 후보. 현재 평가 점수에 포함하면 안 된다.
- `human_reviewed`: 질문, 답, 근거, 유형, 분할을 사람이 모두 확인한 뒤에만 사용할 상태다.

## 다시 만들고 검사하기

```bash
./.venv/bin/python eval/build_gold_v2.py
./.venv/bin/python eval/validate_gold_v2.py
```

로컬 코퍼스가 없는 환경에서는 두 번째 명령에 `--skip-chunk-check`를 붙일 수 있다. 다만 근거 ID 검사는 생략되므로 검수 완료로 볼 수 없다.

## 사람 검수 체크리스트

1. 질문이 실제 사용자가 할 법한 표현인지 확인한다.
2. 초안 답이 근거에 있는 내용만 포함하는지 확인한다.
3. 근거 청크가 답의 모든 주장을 뒷받침하는지 확인한다.
4. 표 문항은 열, 행, 적용 기간을 원문 PDF와 다시 대조한다.
5. 답 없음 문항은 고정 코퍼스 전체에 답이 정말 없는지 확인한다.
6. 후속 질문은 이전 대화 없이 현재 발화만 보면 불완전한지, 독립 질문 재작성이 맞는지 확인한다.
7. 최종 테스트 문항은 검수 뒤에도 개발 중 실행하지 않는다.
